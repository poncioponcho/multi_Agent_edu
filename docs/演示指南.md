## 一、演示前准备（5 分钟）

```bash
bash demo.sh start      # 启动三端服务
bash demo.sh status     # 确认：Python/前端/Go 三端 ✅，LLM 已配置
```

- 浏览器**只开一个标签页**访问 `http://localhost:3000`（多标签会互相覆盖事件流）
- 演示亮点备用：`bash demo.sh` 所在目录下执行 `go run cmd/eval/main.go`（Go 端），输出 18/18 通过、平均 3 轮掌握，与简历数字一致

### 推荐演示动线

1. **先讲架构**：5-Agent Mesh + EventBus 事件驱动（指着左侧 Agent 状态区）
2. **点"答对了"**：事件流秒回（模板路径快），讲 correlation_id 链路追踪
3. **连点"答错了"两次**：触发 Hint Agent 分级提示 + Engagement Agent 挫败感预警
4. **最后再提问**：走真实 LLM（DeepSeek），等待期顺势讲降级机制（见问题 1 话术）

> 顺序很关键：把慢的 LLM 环节放最后，等待时间被讲解填满。

## 二、问题 1：LLM 响应无流式输出，等待时间长

### 现象

在输入框提问后，界面**静默 5–15 秒**（DeepSeek 推理模型思考 + 生成），期间无任何反馈，回复一次性弹出。

### 复现步骤

1. 访问 `http://localhost:3000`，保持 WebSocket「已连接」
2. 选择任意知识点，输入"什么是一元二次方程"，点击提问
3. 观察右侧事件流：约 5–15 秒无变化，之后 Tutor Agent 卡片一次性出现完整回复

### 当前行为 vs 预期行为

| | 当前 | 预期 |
|---|---|---|
| 请求后反馈 | 无（白等） | 立即显示"思考中"指示 |
| 回复到达方式 | 整段一次性 | 逐段流式呈现（或至少有进度感知） |
| 超时降级 | 静默替换为模板（用户无感知差异） | 明确提示"已降级" |

**根因**：链路为 `前端 → WS → Python Orchestrator → LLM（非流式）→ 收齐全部 events 后统一 send`。整条链路没有任何中间状态推送。

### 改进建议

**方案 A：最小修复（演示前可完成，约 10 分钟）— 前端"思考中"状态**

- [App.tsx](../frontend/src/App.tsx) 增加本地状态：`handleQuestion` 发送后立即显示"🤔 Agent 思考中…"（转圈动画），收到下一条 `TutorAgent` 事件后清除
- 不动后端，零风险

**方案 B：真流式（作为面试 talking point，不建议演示前实施）**

- `llm_client.chat` 开启 `stream=True`，按 chunk 通过 WS 推送增量文本
- 前端 EventCard 支持增量拼接渲染
- 涉及 orchestrator 事件模型改造（当前 events 是"完成后返回列表"的模型），改动面大

### 验证方法

方案 A 完成后：提问瞬间（<1 秒）应看到"思考中"指示 → LLM 返回后指示消失、卡片出现。用 DevTools Network 面板确认 WS 消息时序即可。

### 演示话术（等待期）

> "现在是真实 LLM 推理，需要几秒。生产环境我们会做流式输出——这是方案里已经规划的；同时系统设计了降级机制，LLM 不可用时自动切换模板，保证服务可用性。"

## 三、问题 2：DeepSeek 返回的数学公式显示异常

### 现象

LLM 回复中的 LaTeX 公式（如 `\(2x+3=7\)`、`\frac{b}{2a}`）以原始文本形式直接显示，可读性差。

### 复现步骤

1. 提问"一元二次方程有哪些解法"
2. 观察 Tutor Agent 回复：出现 `\(2x+3=7\)` 之类的原始 LaTeX 标记

### 当前行为 vs 预期行为

| | 当前 | 预期 |
|---|---|---|
| 公式显示 | `\(2x+3=7\)` 原始标记 | 渲染为 2x+3=7 数学排版 |
| 复杂公式 | `\frac{-b\pm\sqrt{b^2-4ac}}{2a}` 不可读 | 渲染为标准分式/根式 |

**根因**：[App.tsx](../frontend/src/App.tsx) 的 `EventCard` 用纯文本 `{String(event.data.response)}` 渲染，无 Markdown/LaTeX 解析；LLM 也未被约束输出格式。

### 改进建议

**方案 A：前端 KaTeX 渲染（演示前可完成，约 15 分钟）**

```bash
cd frontend && npm install katex
```

- 新建 `renderMath(text)` 工具：把 `\(...\)` / `\[...\]` 片段用 `katex.renderToString` 转换
- `EventCard` 中对 `response` 用 `dangerouslySetInnerHTML` 输出转换结果（内容仅来自 LLM/模板，演示场景可接受；生产需 sanitize）
- 处理转义陷阱：LLM 可能输出 `\\(` 或 `$...$`，转换函数需兼容这三种定界符

**方案 B：Prompt 约束输出纯文本数学（5 分钟，立即可用）**

- 在 [llm_client.py](../python/core/llm_client.py) 的 `SOCRATIC_SYSTEM_PROMPTS` 中追加一句：
  > "数学表达式一律使用纯文本写法（如 2x+3=7、x = (-b ± √(b²-4ac)) / 2a），禁止使用 LaTeX 标记。"
- 优点：零依赖、立即生效；缺点：约束偶尔不生效，复杂公式可读性上限低

**推荐组合**：演示前先上方案 B 兜底 + 方案 A 渲染（时间够就做，不够就只做 B）。

### 验证方法

1. 方案 B：提问两次"解方程 x²=4"，确认回复中出现纯文本公式而非 LaTeX
2. 方案 A：构造含 `\(\frac{-b\pm\sqrt{b^2-4ac}}{2a}\)` 的回复场景，确认渲染为标准数学排版；控制台无 KaTeX 报错

## 四、演示应急锦囊

| 突发情况 | 话术/操作 |
|---|---|
| LLM 超时降级模板 | "这正好演示了降级机制——LLM 不可用时系统自动切换模板，服务不中断" |
| 事件流错乱 | 关掉多余标签页，刷新重连（自动重连有指数退避） |
| LLM 太慢 | 切到"答对了/答错了"按钮（模板路径秒回），把提问环节放到讲解后 |
| 被追问四级 Prompt | Go 版单 prompt + 3 级 hint；Python 版四档 mastery 路由（如实说明） |
| 被追问 WebSocket 归属 | Go 主实现是 REST + 事件回放；WS 实时通道由 Python + React 实现 |
